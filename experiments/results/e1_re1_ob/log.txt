ExpAC@k  : the ground-truth INDICATOR is in the top k explained features. RQ1.
           Strict: only the CPU and MEM cases, where the right metric is not a
           judgement call. This is the headline (docs/08 section 4).
exp_ac*_loose : every case, counting any plausible metric for the fault type as
           correct. Read it only next to acceptable_indicators in the per-fault
           table; pooled across fault types it means nothing.
AC@k     : the ground-truth SERVICE is in the top k. The coarse question.
symptom_rate : of the WRONG top-1 answers, the share that blamed a service which
           calls the real culprit - so it was a victim, not the cause. RQ2.
           Empty when nothing was wrong or no graph was available.
wrong_top1 : cases where the service the method returned first is not the culprit.
           This is symptom_rate's denominator. It can exceed (1 - AC@1) x cases
           for a method that ties, since a tie at rank 1 is scored as a part hit.
no_clear_cause : NOT comparable between methods. The rule is a fixed threshold on
           the rank-1 score (min_cause_score, 3.0), and these methods do not share
           a scale - SHAP_IFOREST reports mean absolute SHAP, which is almost never
           above 3, so it reads NO_CLEAR_CAUSE on nearly every case while still
           ranking well. Read it per method, never across them.
